# 실현 가능성 · 가성비 판정 (v0.1, 2026-09-15)

> 질문: LLM을 붙였을 때 가성비가 나오는가? 크롬 확장으로 붙여 쓸 수 있는가? 개인용으로 끝낼지 범용으로 갈지.
> 전제: 주 용도는 **메신저 보고**, 1000자 이내 짧은 글. 대량 문서 아님.

---

## 0. 결론 먼저

| 질문 | 판정 |
|---|---|
| 개인용 가성비 | **충분히 된다.** 하루 15회 사용 시 월 ₩5,000~9,000. 커피 두 잔 값에 어투 학습까지 포함. |
| 범용 제품 가성비 | **조건부.** ₩9,900/월 유료 기준 총이익률 30~50%. 무료 티어를 넉넉히 주면 적자. 원가보다 차별화(한국어 어투 학습)와 유지보수가 관건. |
| 크롬 확장 인라인(밑줄) | **무리 맞다.** 슬랙(Quill)·노션은 조건부, 컨플루언스는 충돌, Google Docs·카카오워크는 불가. 솔로 개발 6~8주 + 상시 유지보수. |
| 크롬 확장 사이드패널(선택→교정→되쓰기) | **현실적.** 3~5주. 웹 기반 메신저(슬랙 웹, 네이버웍스 웹, Gmail)에서 동작. |
| 온디바이스(Gemini Nano)로 $0 추론 | **불가.** 2026-09 현재 Chrome 내장 AI는 한국어 미지원. |
| 권장 경로 | **개인용으로 먼저 만들되 범용 전환 가능한 구조로.** 웹 페이지 + 전역 단축키(또는 사이드패널) 진입점. 8주 후 게이트 지표로 범용 여부 결정. |

## 1. LLM 비용 모델

### 1.1 가정
- 공식 가격표(2026-06 기준): Haiku 4.5 $1/$5, Sonnet 5 $2/$10, Opus 5 $5/$25 (입력/출력, MTok당). 캐시 읽기 0.1×, 캐시 쓰기 1.25×. Batch API 50% 할인.
- 프롬프트 캐시 최소 길이: Opus 5 512토큰, Sonnet 5 1,024토큰, **Haiku 4.5 4,096토큰**(우리 고정 프롬프트 약 2,500토큰이라 Haiku는 캐시 불가).
- 토큰 수: **한글 1자 ≈ 1토큰으로 보수 추정**(최신 토크나이저는 이전 대비 최대 1.35× 증가 반영). 실측 시 20~30% 낮게 나올 가능성이 큼.
- 프롬프트 구성: 고정 지침 1,500 + 스타일 규칙 스냅샷 1,000(캐시 대상) + 검색 예시·프로필·개인 사전 900(동적) + 초안. 출력: 교정문 + 변경 카드(건당 50토큰) + L3는 리라이트 3안 + adaptive thinking 300토큰.
- 캐시 적중률 60%(개인 사용은 5분 TTL 안에 연속 요청이 드물어 보수적으로).
- 환율 ₩1,380/$.
- 이 환경에는 API 자격증명이 없어 **실측이 아닌 추정치**. Phase 1 첫 주에 `usage` 로그로 재보정한다.

### 1.2 건당 비용 (메신저 보고, 캐시 60% 적중)

| 모델 | 강도 | 짧은 보고(80자) | 보통 보고(300자) | 긴 보고(1000자) |
|---|---|---:|---:|---:|
| haiku-4.5 | L1 교정만 | ₩9 | ₩12 | ₩22 |
| haiku-4.5 | L2 다듬기 | ₩10 | ₩13 | ₩22 |
| haiku-4.5 | L3 대안 3안 | ₩12 | ₩20 | ₩44 |
| sonnet-5 | L1 | ₩15 | ₩21 | ₩40 |
| sonnet-5 | L2 | ₩16 | ₩23 | ₩42 |
| sonnet-5 | L3 | ₩21 | ₩36 | ₩84 |
| opus-5 | L1 | ₩36 | ₩52 | ₩100 |
| opus-5 | L3 | ₩52 | ₩90 | ₩211 |

읽는 법: 300자 보고를 Sonnet 5로 다듬고 대안 3안까지 받아도 **₩36**. 비용의 대부분은 고정 프롬프트(입력)와 리라이트(출력)이지 초안 길이가 아니다. 그래서 1000자 이내 조건에서는 길이가 비용을 거의 좌우하지 않는다.

### 1.3 월간 비용 (믹스: 80자 50% / 300자 40% / 1000자 10%, 주 1회 Opus 5 Batch 증류 ₩650 포함)

| 사용 패턴 | 요청/월 | haiku-4.5 | 하이브리드* | sonnet-5 | opus-5 |
|---|---:|---:|---:|---:|---:|
| 개인 가벼움 (5회/일) | 110 | ₩2,200 | ₩2,700 | ₩3,500 | ₩7,700 |
| **개인 보통 (15회/일)** | 330 | ₩5,400 | ₩6,700 | **₩9,100** | ₩21,800 |
| 개인 헤비 (40회/일) | 880 | ₩13,300 | ₩16,800 | ₩23,200 | ₩57,000 |
| 제품 활성 사용자 1인 (10회/일) | 220 | ₩3,800 | ₩4,700 | ₩6,300 | ₩14,700 |

\* 하이브리드 = L1·L2는 Haiku 4.5, L3만 Sonnet 5.

참고로 "타이핑할 때마다 자동 검사"(실시간 모드, 일 150회)는 Sonnet 기준 월 ₩48,000으로 뛴다. **전송 직전 명시적 교정 버튼** 방식이어야 가성비가 성립한다.

### 1.4 모델 선택 권고
- **Sonnet 5 기본**: 한국어 존대·어투 판단은 Haiku보다 확실히 낫고, 비용 차이는 월 ₩3,000~4,000 수준. 개인용은 고민할 금액이 아니다.
- **Opus 5는 증류(주 1회 Batch)와 평가에만**: 인터랙티브 경로에 쓰면 비용 2.4배, 지연도 커서 메신저 용도에 부적합.
- **Haiku 4.5는 범용 제품에서 L1 라우팅용**: 캐시 최소 4,096토큰 때문에 고정 프롬프트 캐시가 안 되는 점을 감안해도 L1에서는 가장 싸다.
- 실측 후 토큰이 추정보다 적게 나오면(가능성 높음) 위 수치는 20~30% 더 내려간다.

## 2. 범용 제품 손익

### 2.1 유료 사용자만 있을 때 (월 220회, ₩9,900/월)

|---:|---:|---:|---:|---:|---:|---:|
| 100 | $455 | $340 | $45 | $717 | 30% | 46% |
| 1,000 | $4,554 | $3,403 | $150 | $7,174 | 34% | 50% |

### 2.2 무료 티어를 두면
무료:유료 = 19:1, 무료는 월 30회 제한이라고 가정하면 **유료 1인이 부담하는 원가는 Sonnet $15, 하이브리드 $11**로 ₩9,900($7.2) 매출을 넘는다. 즉 **무료 티어는 월 10회 이하 또는 Haiku L1 전용**으로만 가능하다.

### 2.3 시장 가격 비교
| 제품 | 가격 |
|---|---|
| Grammarly Pro | $12/월(연납) |
| 엔그램 프리미엄 | $6.49/월(연납) |
| DeepL Write Pro | $7.49/월 |
| LanguageTool Premium | €4.90/월(연납) |
| 카카오워크 AI 다듬기 | 요금제 번들, 별도 과금 없음 |
| 뤼튼 | 무료 |

한국 시장에서 ₩9,900 이상 받기는 어렵고, 카카오워크·뤼튼처럼 무료 번들 경쟁자가 있다. 업계 참고치는 글쓰기 AI 유료 사용자당 추론 원가 $3~7, 총이익률 40~60%. 우리 모델(하이브리드 $3.4, 50%)은 이 범위 안이다.

### 2.4 판정
- 원가 자체는 범용 제품이 **불가능한 수준은 아니다.** 하이브리드 라우팅과 캐시가 전제.
- 그러나 마진 30~50%는 마케팅·결제 수수료·고객 지원·유지보수를 빼면 얇다. 100명 유료로는 월 $200~300 남는다.
- 범용 제품의 승부처는 원가가 아니라 **한국어 어투 학습이 실제로 체감되는가**와 **진입점(메신저 안에서 얼마나 매끄러운가)**이다. 이 두 가지는 개인용으로 써보면서 검증할 수 있다.

## 3. 진입점: 크롬 확장은 어디까지 되나

### 3.1 온디바이스 AI로 비용 0 만들기 → 불가
Chrome 내장 AI(Gemini Nano)의 Prompt/Proofreader/Rewriter API는 2026-09 기준 **영어·일본어·스페인어(149부터 독일어·프랑스어)만 지원**하고 한국어는 `NotSupportedError`. 하드웨어 조건(디스크 22GB 여유, VRAM 4GB 또는 RAM 16GB)도 사무용 노트북 다수를 탈락시킨다. 언어 감지·번역 보조로만 쓸 수 있다.

### 3.2 호스트별 인라인(밑줄) 통합 난이도

| 호스트 | 에디터 | 난이도 | 비고 |
|---|---|---|---|
| Gmail | 단순 contenteditable | 하 | LanguageTool·Grammarly 기본 지원 |
| Slack 웹 | Quill | 중~상 | 커서 점프 이슈, Grammarly도 데스크톱 앱 경로로 지원 |
| Notion | 블록별 contenteditable | 중~상 | 밑줄은 뜨나 클릭 적용 실패 사례 |
| Confluence/Jira | ProseMirror + 협업 동기화 | 상 | Atlassian이 Grammarly 차단 권고한 이력 |
| Google Docs | Canvas 렌더링 | 사실상 불가 | Grammarly 등 3사만 허용목록 |
| 카카오워크 | 데스크톱/모바일 앱 중심 | 불가 | 웹은 관리자·회의 위주 |
| 네이버웍스 웹 | 비공개 에디터 | 중(실측 필요) | |

Grammarly는 호스트 DOM을 건드리지 않고 **오버레이 레이어에 밑줄을 그리고 좌표를 미러링**하는데, 이게 솔로 개발자가 상시 유지보수하기엔 무겁다.

### 3.3 확장 아키텍처 제약
- API 키를 확장에 넣을 수 없다 → 백엔드 프록시 필수(BYOK는 기업망에서 외부 API 직접 호출이 막히기도 함).
- 페이지 텍스트를 원격 LLM에 보내면 Chrome Web Store 심사에서 개인정보처리방침 + **UI 내 명시적 동의** + 제3자 AI 공개 + Limited Use 준수 필요. 2026-08부터 강화 집행. "어투 학습" 기능은 저장 범위·보존 기간을 정책에 명시해야 한다.
- MV3 remotely hosted code 금지: 프롬프트 템플릿을 서버에서 받는 건 데이터라 허용, 로직은 불가.

### 3.4 진입점 4가지 비교 (솔로 개발자)

| 티어 | 동작 범위 | 공수 | 판정 |
|---|---|---|---|
| (a) 인라인 밑줄 확장 | Gmail·일반 입력창 ○, Slack·Notion △, Docs·카카오워크 ✗ | 6~8주 + 확장 4~6주 + 상시 유지보수 | **보류.** 범용 전환 확정 후에만 |
| (b) 사이드패널/플로팅 버튼 확장 | 모든 웹 contenteditable/textarea. 선택 → 교정 → 되쓰기 | 3~5주 + 심사 1~2주 | **범용 제품의 1차 진입점** |
| (c) 웹 페이지 복붙 | 어디서든. 마찰 큼 | 1~2주 | **개인용 MVP** |
| (d) **전역 단축키 데스크톱 유틸** | **모든 앱**(카카오워크·슬랙 데스크톱 포함). 선택 텍스트 → 단축키 → 교정 결과로 치환 | 1~2주(Raycast 확장·AutoHotkey·Electron 트레이) | **메신저 보고 용도에 가장 잘 맞음.** 개인용 2차 진입점 |

메신저 보고가 주 용도라면 (d)가 핵심이다. 메신저가 데스크톱 앱이면 크롬 확장은 애초에 닿지 않고, 웹이어도 매번 사이드패널을 여는 것보다 단축키 한 번이 빠르다. macOS는 Raycast 확장 또는 Shortcuts, Windows는 AutoHotkey 또는 PowerToys로 "선택 텍스트 → API 호출 → 클립보드/치환"을 만들 수 있고, 백엔드는 웹 페이지와 공유한다.

## 4. 개인용 vs 범용 결정 프레임

### 4.1 지금 결정하지 않는다
개인용으로 만들되 아래 세 가지만 처음부터 지키면 범용 전환 비용이 낮다.
1. 모든 테이블에 `user_id` 스코프, 사용량·토큰·비용 메터링 테이블.
2. 교정 API를 웹 페이지·확장·단축키 유틸이 공유하는 단일 백엔드로.
3. 학습 데이터(규칙·예시)를 사용자별로 격리하고 내보내기/삭제 가능하게(CWS 정책과 개인정보 대응).

### 4.2 8주 후 게이트 지표
| 지표 | 범용 진행 기준 | 개인용 유지 기준 |
|---|---|---|
| 무수정 복사율(내가 결과를 안 고치고 그대로 보낸 비율) | 8주차 65% 이상 | 50% 미만 |
| 제안-최종 편집거리 추이 | 4주 연속 감소 | 정체 |
| 프로필 OFF 블라인드 대비 수락률 차 | +15%p 이상 | +5%p 미만(학습이 체감 안 됨) |
| 실측 건당 비용(Sonnet) | ₩30 이하 | ₩50 초과 |
| 내 실제 사용 빈도 | 주 5일 이상 자발적 사용 | 안 쓰게 됨 |
| 주변 3명 테스트 반응 | "돈 내겠다" 1명 이상 | 없음 |

### 4.3 범용으로 갈 경우 추가 비용 항목
- 백엔드 프록시·인증·결제(Stripe 또는 토스페이먼츠)·사용량 제한: 2~3주.
- CWS 심사 대응(정책 문서, 동의 UI): 1~2주.
- Haiku/Sonnet 라우팅과 캐시 최적화로 원가 $3.4/유료 사용자 확보.
- 무료 티어는 월 10회 이하.

## 5. 다음 단계 (권장)

1. **Phase 1을 웹 페이지 + 공유 백엔드로 시작** (기획서 10장). 첫 주에 실측 토큰·지연·비용을 `usage` 로그로 확보해 이 문서의 추정치를 교정한다.
2. **2주차에 전역 단축키 유틸 추가** (사용 OS 확인 필요). 이것이 실제 "메신저 보고" 워크플로를 만든다.
3. 크롬 확장은 범용 전환이 결정된 뒤 (b) 사이드패널부터. 인라인 밑줄은 하지 않는다.
4. 8주차에 4.2 게이트 지표로 범용 여부 결정.

**사용자 확인 필요**
- 주로 쓰는 메신저(슬랙 웹/데스크톱, 카카오워크, 팀즈, 네이버웍스)와 OS(macOS/Windows). (d) 구현 방식이 달라진다.
- 사내 규정상 LLM 외부 전송이 금지된 정보 항목.
